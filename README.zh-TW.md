## 裝置相容性

- **目標裝置：** AYN Thor（具備雙螢幕的遊戲掌機）
- **最低 Android 版本：** 13 / API 33（即 Thor 出廠搭載之系統版本）
- **單螢幕裝置：** **永久不支援。** Megingiard 的架構嚴格設計為跨螢幕協同隨行系統，主螢幕（上方螢幕）與副螢幕（下方螢幕）必須同時並行運作。不支援單螢幕手機、平板電腦與模擬器。
- **其他裝置：** 不支援。Megingiard 依賴特定硬體路徑（`/dev/input/event*`、副顯示器、AYN Thor 輸入按鍵配置），這些路徑可能在其他手機或掌機上並不存在。此外，我也沒有其他雙螢幕掌機 😅

## 核心特色

### 1. 零延遲多區域裁切主螢幕鏡像

- **直接硬體管道：** 結合使用 Android 的 `MediaProjection` 與原生 `VirtualDisplay` 直接輸出至 `SurfaceView`，繞過所有軟體合成與複製處理步驟。
- **多區域裁切版面配置編輯器：** 定義最多 10 個主螢幕裁切區域（「Cutouts」），並透過避免權杖衝突與畫面凍結的單一 Surface 複製架構，自由排列於副螢幕上。
- **外觀長寬比鎖定模式：** 針對個別裁切區域設定外觀長寬比鎖定：_自由 (Free)_ 用於獨立調整尺寸、_上方/來源鎖定 (Top)_ 用於等比例縮放目標邊界，以及 _下方/目標鎖定 (Bottom)_ 用於自動調整來源裁切。
- **邊緣漸變融合與圓形外觀：** 套用累加式邊緣漸層（最多 100 dp），消除相鄰裁切區域之間的暗邊暗縫達成無縫過渡，或將裁切區域切換為正圓形渲染。
- **時間動作平滑化：** 可在關閉 (Off)、輕度 (Light)、中度 (Medium) 或強烈 (Strong) 時間濾波（指數移動平均）之間切換，穩定個別裁切區域中的 UI 介面元素。
- **跟隨觸控模式：** 主螢幕即時觸控追蹤。鏡像視埠會根據您目前的縮放等級，自動置中於主螢幕最後觸控的位置，並具備選用的動作平滑處理。可設定於執行巨集期間暫時停用，以避免動作衝突。
- **可自訂控制項：** 將鏡像控制項（開始 / 停止 / 凍結 / 視埠重設）完全整合為自訂 MacroPad 版面中的實體按鈕，或使用快捷選單浮動層中常駐的控制項。
- **實機動態展示：** 觀看由 dylosama 在 YouTube Shorts 上的 [螢幕鏡像動態展示影片](https://www.youtube.com/shorts/v_UhWzfCbRQ)。

### 2. MacroPad 巨集中心模式

- **可自訂按鍵面板：** 建立具備多組自訂版面的具名設定檔，支援自由擺放不同大小、形狀與動作的按鍵。
- **豐富的動作映射：** 可將按鍵綁定至標準鍵盤按鍵、遊戲手把按鈕、滑鼠按鍵、滾輪，或小紅點軌跡點（相對滑鼠移動/虛擬觸控）。
- **強大的版面配置編輯器：** 拖曳放置按鍵版面畫布，具備矩形或放射狀對齊格線，並整合由 Material Symbols 提供超過 4,000 種圖示的圖示挑選器。
- **應用程式感知設定檔自動切換：** 將設定檔綁定至特定的 Android 應用程式。當主螢幕啟動對應應用程式時，Megingiard 會立即在副螢幕切換至其關聯的 MacroPad 設定檔。此事件驅動功能採用專用且高效能的**無障礙服務 (Accessibility Service)**（具備系統 UI 排除機制以防止焦點循環），並在設定中提供即時連線狀態指示燈。
- **視覺化巨集編輯器與錄製器：** 手工打造或錄製並編輯按鍵、滑鼠與遊戲手把事件的定時序列。可直接從螢幕點擊進行錄製，或在特權模式下直接透過實體控制器錄製巨集。包含**計時與持續時間隨機產生器**（每步驟加入 10ms 至 100ms 的動態隨機偏移），以模擬自然的人類操作變化。

### 3. 虛擬鍵盤

- **螢幕自訂配置：** 完整的虛擬鍵盤，提供 **QWERTZ / QWERTY / AZERTY** 版面、數字列、F1–F12、方向鍵與標準修飾鍵。
- **智慧修飾鍵：** 輕點修飾鍵（Shift、Ctrl、Alt、Meta）使其變為黏滯鍵（單次生效），或長按以保持按住狀態。
- **整合軌跡點 (Trackpoint)：** 直接使用鍵盤版面上的視覺化軌跡點，導航主螢幕上的滑鼠游標。
- **核心重複控制：** 可自訂按鍵重複速率；停用重複時，按鍵放開訊號會立即送出，以抑制 Linux 核心的自動重複功能。

### 4. 虛擬觸控板

- **核心級滑鼠模擬：** 將副螢幕轉變為相對軌跡板，控制 Android 系統認可的實體系統滑鼠。
- **亞毫秒級反應速度：** 觸控事件透過原生二進位檔案 (`/dev/uinput`) 直接注入核心輸入串流，延遲低於 1ms。
- **多點輕觸手勢：** 簡潔可靠的手勢：單指輕點為滑鼠左鍵、雙指輕點為滑鼠右鍵、三指輕點為滑鼠中鍵。

### 5. 快捷選單與沉浸式 UI

- **邊緣常駐快捷選單條：** 位於副螢幕底部的微小滑動提示浮動層。向內滑動即可開啟快捷選單，讓您切換設定檔/工具、切換鏡像或開啟設定，完全無需離開當前版面。
- **極黑電競美學風格：** 無邊框沉浸式全螢幕樣式，尊重副螢幕遊戲環境的黑暗氛圍，避免分散主螢幕的注意力。

## 安裝指南

1. 從 GitHub 上的 [Releases](../../releases) 分頁下載最新簽署的 `Megingiard-vX.Y.Z.apk`。
2. 在 AYN Thor 上，允許您的瀏覽器或檔案管理員安裝未知應用程式（Android 設定 → 應用程式 → \<您的檔案管理員\> → 「安裝未知應用程式」）。

## 初次啟動與快速上手

1. **啟動應用程式：** 從啟動器開啟 Megingiard。它僅在副螢幕上運作，因此請務必從副螢幕啟動，或設定您的啟動器將其釘選/在下方螢幕執行。
2. **設定無障礙服務（選用）：** 若您希望使用**應用程式感知設定檔自動切換**，必須啟用 Megingiard 的無障礙服務：
   - 前往 Android 設定 → 無障礙 → 已安裝的應用程式 / 下載的服務。
   - 選擇 **Megingiard Accessibility Service** 並將其啟用。
   - 在 Megingiard 的全域設定中開啟 **自動切換設定檔 (Auto-switch profiles)**。
3. **開啟快捷選單：** 將副螢幕底部的**邊緣快捷選單條向內滑動**。在此您可以：
   - 切換使用中工具（螢幕鏡像、MacroPad、鍵盤、觸控板）。
   - 挑選版面配置與設定檔。
   - 開始、凍結或停止螢幕鏡像。
   - 開啟全域設定。
4. **結束應用程式：** 透過標準 Android「最近使用的應用程式」檢視關閉 Megingiard —— 應用程式內部未設置退出按鈕，以確保您的螢幕空間完全乾淨不雜亂。

## 特權模式

特權模式為一項**選擇性啟用 (opt-in) 的功能**，可解鎖一般 Android 沙盒因安全限制而無法提供的進階功能。**預設為停用狀態**，可隨時在全域設定中開啟或關閉。

### 運作原理（技術細節）

Megingiard 在 APK 內部封裝了一個輕量級原生裝置端輔助守護行程 (`megingiard_privd`)。當您啟用特權模式時，應用程式內的設定精靈會利用 Android 內建的**無線偵錯 (Wireless Debugging)** 機制（自 Android 11 起提供）將守護行程部署至 `/data/local/tmp`，並以 **shell 使用者** (UID 2000) 權限執行 —— 這與執行 `adb shell` 工作階段所具備的安全層級相同。接著應用程式會建立安全的處理序本機 Unix 通訊端 (Unix socket) 連線以與守護行程通訊。

此架構**無需 Root 權限、無需 USB 連接線、無需電腦，亦無需任何外部伺服器**。整個引導部署過程完全在裝置本身透過全域設定底部的精靈執行。

### 解鎖的功能

| 功能 | 在特權模式下獲得的提升 | 未啟用特權模式時的後備行為 |
| :--- | :--- | :--- |
| **手把融合 (Gamepad Merge)** | 遊戲僅會識別到**單一**控制器，將 MacroPad 虛擬輸入無縫融合於實體控制器之上。 | 實體控制器旁會額外出現第二個虛擬控制器。部分遊戲可能會忽略其中一個裝置的輸入。 |
| **手把錄製 (Gamepad Recording)** | 即時從您的**真實實體控制器**錄製巨集，同時目標遊戲仍持續正常接收操作輸入。 | 僅能使用螢幕上的虛擬控制器錄製浮動層進行錄製。 |
| **特權鏡像 (Privileged Mirror)** | 螢幕鏡像瞬間啟動，無需每次手動同意 MediaProjection 螢幕錄製權限對話框。 | 每次啟動螢幕鏡像時均會跳出標準 Android 螢幕錄影授權對話框。 |

### 技術上為何需要此模式

標準 Android 應用程式沙盒（於 `untrusted_app` SELinux 網域中執行，且不具備 `input` 群組成員資格）被嚴格禁止直接寫入 `/dev/uinput` 或實體 `/dev/input/event*` 節點，亦無法發起系統級 `SurfaceControl` 鏡像路徑。Android shell UID 則具備必要的 `input` 群組權限以及更寬鬆的 SELinux 設定檔，從而能夠實現原生輸入注入與畫面投影控制。

### 便利優勢

- **自動重新連線：** 一旦設定完成，Megingiard 在冷啟動時會無聲自動重新連線至本機守護行程。無需每次手動重新配對。
- **無週期性干擾提示：** 特權鏡像在每次啟動時均會完全略過系統螢幕擷取警告對話框。
- **個別功能獨立開關：** 可自由精確選擇哪些功能在特權模式下執行，哪些維持後備模式。
- **⚠️ 守護行程生命週期：** 重新開機後守護行程**無法**保留，因為 Android 會在開機時清除 `/data/local/tmp`。在裝置重新開機後，您需要重新執行配對精靈（過程耗時少於 30 秒）。

### 安全性與信任說明

特權模式功能強大，您應當充分理解其安全性範疇：

- **Shell 層級權限範圍 (UID 2000)：** 守護行程以與 `adb shell` 相同的權限執行。它可以讀寫輸入節點以模擬控制器與按鍵，但**無法**提權至 Root、無法修改系統/唯讀分割區，亦無法讀取屬於其他應用程式的私有資料。
- **僅信任安全來源：** 僅在您信任原始碼與簽署發布版本時才執行特權模式。**請一律僅從官方 GITHUB RELEASES 頁面下載 APK。**
- **完全本機與離線運作：** 無線偵錯配對為本機內部環回 (loopback) 交握。守護行程僅監聽任何外部網路均無法存取的處理序本機**抽象 Unix 通訊端**。Megingiard 不會發起任何對外網路連線。
- **隨時輕鬆停用：** 您可隨時停用特權模式。所有功能均會優雅降級回標準沙盒後備運作模式。

### 驗證下載的 APK

每個發布版本均附帶 SHA-256 校驗碼檔案（例如 `Megingiard-vX.Y.Z-checksum-sha256.txt`）。安裝前請先驗證下載 APK 的雜湊值以確保其完整性。

**macOS**

```sh
shasum -a 256 Megingiard-vX.Y.Z.apk
```

**Linux**

```sh
sha256sum Megingiard-vX.Y.Z.apk
```

**Windows (PowerShell)**

```powershell
Get-FileHash Megingiard-vX.Y.Z.apk -Algorithm SHA256 | Select-Object -ExpandProperty Hash
```

在側載安裝之前，請確認輸出雜湊值與 `.txt` 檔案中的校驗碼完全相符。為了確保絕對的真實性，建議同時驗證開發者的簽署憑證指紋。

### 配對精靈操作步驟

1. 前往 Android 設定 → 系統 → 開發人員選項，並啟用**無線偵錯**。
2. 輕點**「使用配對碼配對裝置」** —— Android 畫面上將顯示 IP 位址、通訊埠以及 6 位數配對碼。
3. 將通訊埠與配對碼輸入至 Megingiard 的設定精靈中。
4. 設定精靈將與本機 ADB 服務配對、部署守護行程、啟動守護行程並執行自我檢測。
5. 在設定中可隨時輕點**測試連線 (Test Connection)**，以驗證通訊端連結是否保持作用中狀態。

## 常見問題與疑難排解

**鏡像畫面呈現全黑？**

> 請嘗試從快捷選單中停止並重新啟動鏡像。若畫面仍為全黑，請在 GitHub 開啟 Issue 回報問題，並註明您目前的應用程式版本與重現步驟。

**每次啟動鏡像時 Android 都會詢問螢幕錄影權限？**

> 這是 Android 的預設系統行為。啟用特權模式並在設定中開啟**特權鏡像 (Privileged Mirror)** 功能，即可永久略過此提示對話框。

**重新開機 Thor 後特權模式顯示為「關閉 (OFF)」？**

> 此為正常現象。Android 會在重新開機時清除 `/data/local/tmp`。在未取得 Root 權限的情況下，側載守護行程無法在開機時自動啟動。只需重新執行配對精靈（耗時約 30 秒）即可。

**使用 MacroPad 時遊戲偵測到兩支控制器？**

> 啟用特權模式並開啟**手把融合 (Gamepad Merge)**。此功能會將 MacroPad 的虛擬動作合併至實體控制器的輸入串流中，從而向遊戲隱藏雙控制器狀態。

**僅有 MacroPad 按鈕或僅有實體手把輸入能生效，無法兩者同時作用？**

> 部分 Android 遊戲僅接受單一使用中的輸入來源。在特權模式下啟用**手把融合 (Gamepad Merge)** 即可解決此問題。

**無線偵錯配對失敗？**

> 請確保輸入的是快顯配對碼對話框中顯示的**配對通訊埠**，而非無線偵錯主畫面上顯示的連線通訊埠。這兩個是不同且動態分配的五位數號碼。

**部署守護行程失敗？**

> 有時本機 ADB 環回交握需要數秒鐘才能完成初始化。請嘗試再執行測試/部署步驟 1 到 2 次 —— 這通常能解決暫時性的通訊端連線逾時問題。

**我可以在其他雙螢幕裝置或手機上執行此應用程式嗎？**

> 無法。Megingiard 是專門針對 AYN Thor 的特定螢幕幾何結構、硬體專屬映射路徑以及實體事件碼進行設計。它無法在不同的硬體配置上運作。

**為什麼設定檔自動切換沒有作用？**

> 1. 請確認 Megingiard 的**無障礙服務**已啟用（Android 設定 → 無障礙 → Megingiard Accessibility Service）。
> 2. 請確認全域設定中的**自動切換設定檔**已開啟。
> 3. 請確認您的設定檔已在設定檔編輯器中正確選取了應用程式映射（必要時可輕點「清除應用程式映射」並重新選取該應用程式）。
> 4. 請注意，當 Megingiard 本體、核心系統浮動介面 (`com.android.systemui`) 或系統對話框 (`android`) 處於前景時，系統會自動忽略設定檔切換，以防止焦點循環衝突。
